## What this project is

A distributed systems demo implementing a full B2B authorization stack:
- **Zitadel** — OIDC identity provider
- **OpenFGA** — fine-grained authorization (ReBAC)
- **Apache APISIX** — API gateway with custom Lua plugin that enforces OIDC + OpenFGA checks
- **service_a / service_b** — Go gRPC backends communicating via mTLS
- **frontend** — React SPA with PKCE OIDC flow against Zitadel

All inter-service communication uses mTLS with a shared internal CA (`certs/ca.crt`).

## First-time setup

```bash
cd scripts && ./generate_certs.sh   # generates certs/ (gitignored)
cp .env.example .env                # fill in credentials from Zitadel console
docker compose up -d
```

The `openfga-setup` container runs once on startup: it tests the model locally, waits for OpenFGA, creates the store if missing, and writes the authorization model.

## Common commands

```bash
# Start all services
docker compose up -d

# Rebuild a single service after code change
docker compose build service_a && docker compose up -d service_a

# View logs
docker compose logs -f openfga
docker compose logs -f openfga-setup

# List OpenFGA stores (from inside the Docker network)
docker run --rm --network demo_default openfga/cli store list \
  --api-url "http://openfga:8081" \
  --api-token-issuer "http://zitadel:8080/oauth/v2/token" \
  --client-id "openfga" \
  --client-secret "<secret from .env>"

# Test OpenFGA model locally (no running container needed)
docker run --rm -v ./openfga:/openfga openfga/cli model test --tests /openfga/model.fga.yaml

# Frontend dev server (port 5173)
cd frontend && npm install && npm run dev
npm run lint
```

## Architecture: request flow

```
Browser → APISIX (:9080)
           ├─ openid-connect plugin: validates JWT, sets X-Userinfo header
           ├─ authz-openfga plugin: checks user → organization → service permission
           └─ grpc-transcode: HTTP → gRPC
                └─ service_b (:50052, mTLS)
                      └─ service_a (:50051, mTLS)
```

APISIX reads `x-user-id` and `x-tenant-id` from the JWT and passes them as gRPC metadata to the services. The `authz-openfga` Lua plugin resolves dynamic variables (e.g., `$http_x_tenant_id`) to build the OpenFGA tuple check at request time.

## Authorization model

Defined in `openfga/model.fga` and tested in `openfga/model.fga.yaml`:

```
organization has admin and member roles
service has an owner (organization)
can_call = member from owner
```

The APISIX plugin (`apisix_conf/plugins/authz-openfga.lua`) caches the authorization model ID for 10 minutes and supports both single and batch (`AND`/`OR`) permission checks.

## Key env vars (`.env`)

| Variable | Purpose |
|---|---|
| `APISIX_OIDC_CLIENT_ID` / `_SECRET` | APISIX app credentials in Zitadel |
| `APISIX_CLIENT_CERT` / `_KEY` | PEM-encoded mTLS cert for APISIX → OpenFGA calls |
| `FGA_CLIENT_ID` / `_SECRET` | Machine account credentials for OpenFGA store management |

## Proto registry

Both services use a shared proto registry hosted at `github.com/ravillarreal/proto-registry`. The generated Go code lives in `gen/go/user/v1`. Changes to the proto require updating that external module.

## Certificates

Generated by `scripts/generate_certs.sh` into `certs/` (gitignored). Each service has its own cert signed by the internal CA. The CA cert is shared across all services for mutual verification. Re-run the script if certs expire or when adding a new service.
